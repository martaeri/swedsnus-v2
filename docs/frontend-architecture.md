# Swedsnus V2 frontend architecture

V2 keeps the data-driven architecture of `martaeri/swedsnus` but replaces the visual layer and page composition.

## Ownership

- `app.js` — single browser entry point and dependency order.
- `layout.js` — shared age banner, header, navigation and footer.
- `product-store.js` — product loading, IDs, URLs, price/name normalization and the one product-card renderer.
- `catalog.js` — category routing, filter generation, catalog rendering, homepage product rails and dynamic product-page rendering.
- `cart.js` — cart state, drawer rendering, add/remove actions and bookmark state.
- `account.js` — saved-product page and demo account state.
- `styles.css` — the complete V2 visual system and responsive layout. V2 intentionally has no theme switcher or theme-specific override files.
- `tools/excel-to-products-json.py` — Excel-to-JSON export pipeline retained from the original prototype.
- `data/products.json` — deploy product manifest/snapshot.

## Rules

1. Product data is never duplicated in HTML templates.
2. All product cards are generated by `product-store.js`.
3. Category inclusion rules live in `catalog.js`, not individual pages.
4. Header/footer changes belong in `layout.js`.
5. Shared component styling belongs in `styles.css`; do not add one-off patch stylesheets.
6. Desktop and mobile behavior are responsive states of the same components, not separate implementations.
7. Tobacco-free nicotine warnings may be placed by page layout, but their wording should remain consistent.
8. SEO/information copy must remain visible to users and may not be hidden solely for crawlers.

## V2 visual direction

The visual system intentionally differs from the original prototype:

- one fixed palette rather than multiple themes;
- off-white surfaces, black typography and one muted tobacco-brown accent;
- condensed utilitarian headings;
- square corners and visible rules instead of floating rounded cards;
- higher product density;
- fewer decorative modules;
- product data, price and format prioritized over lifestyle presentation.

The intent is to make the interface read as a specialist product shop rather than a general lifestyle or fashion storefront.
