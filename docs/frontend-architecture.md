# Swedsnus V2 frontend architecture

V2 keeps the data-driven architecture of `martaeri/swedsnus` but replaces the visual layer and page composition.

## Ownership

- `app.js` — single browser entry point, dependency order and loading of shared interactive component styles.
- `theme.js` — global theme state and persistence. The cold blue/grey palette is the default; warm beige/brown and muted green are alternatives.
- `layout.js` — shared age banner, header, navigation, counters, theme selector and footer.
- `product-store.js` — product loading, IDs, URLs, product grouping, price/name normalization, prototype multipack calculations and the one product-card renderer.
- `catalog.js` — category routing, filter generation, catalog rendering, homepage product rails, product variant resolution and dynamic product-page rendering.
- `cart.js` — cart state, drawer rendering, selected multipack handling and add/remove actions.
- `account.js` — authentication prototype, shared login modal, bookmark state, saved-product counters and saved-product page.
- `styles.css` — global V2 visual system, all three palettes and responsive page layout.
- `ui-components.css` — shared interactive controls that need richer component states than native controls, currently multipack dropdowns and product variant selectors.
- `tools/excel-to-products-json.py` — Excel-to-JSON export pipeline retained from the original prototype.
- `data/products.json` — deploy product manifest/snapshot.

## Rules

1. Product data is never duplicated in HTML templates.
2. All product cards are generated by `product-store.js`.
3. Category inclusion rules live in `catalog.js`, not individual pages.
4. Header/footer changes belong in `layout.js`.
5. Global layout/theme styling belongs in `styles.css`; reusable interactive component styling belongs in `ui-components.css`. Do not add page-specific patch stylesheets.
6. Theme behavior belongs in `theme.js`; pages must not set their own palette.
7. Authentication prompts and bookmark state belong in `account.js`; pages must not implement separate login popups.
8. Multipack display prices are currently prototype calculations owned by `product-store.js`. Replace that calculation with mapped product/PIM price data when real tier pricing is available.
9. Product-page variants must be resolved from rows sharing the same `product_id`. A selector change navigates to a real variant row and therefore changes URL, title, pricing and specifications together.
10. Variant dimensions are generated only when a field actually differs within a product group; do not hardcode selector sets per product.
11. Desktop and mobile behavior are responsive states of the same components, not separate implementations.
12. Tobacco-free nicotine warnings may be placed by page layout, but their wording should remain consistent.
13. SEO/information copy must remain visible to users and may not be hidden solely for crawlers.

## V2 visual direction

The visual system intentionally differs from the original prototype while keeping the same typography and structural identity across themes:

- cold blue/grey is the primary palette;
- warm beige/brown preserves the original V2 concept as an alternate palette;
- muted green provides a third restrained option;
- condensed utilitarian headings;
- square corners and visible rules instead of floating rounded cards;
- higher product density;
- fewer decorative modules;
- product data, price and format prioritized over lifestyle presentation.

The intent is to make the interface read as a specialist product shop rather than a general lifestyle or fashion storefront.
